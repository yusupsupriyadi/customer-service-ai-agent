    Apa yang akan kamu buat

    Bayangkan sebuah toko online yang setiap hari ditanya hal yang sama: jam buka, ongkir, cara retur. Di tutorial ini kamu membuat petugas customer service otomatis. Pemilik toko menulis informasi usahanya, lalu AI menjawab pertanyaan pelanggan hanya dari informasi itu.

    Tutorial dibagi menjadi empat tingkat:

    • Tingkat 1 (dasar): agent menjawab dari konteks teks yang diketik pemilik toko. Kamu belajar menata halaman dengan Tailwind, menulis system prompt, memanggil API dengan fetch, dan menampilkan keadaan layar kosong, memuat, dan error.
    • Tingkat 2 (lanjutan): agent juga bisa membaca dokumen PDF. Kamu belajar memakai library pdf.js untuk mengambil teks dari file PDF langsung di browser.
    • Tingkat 3 (lanjutan): pelanggan bisa bertanya lewat rekaman suara. Kamu belajar merekam mikrofon dengan MediaRecorder dan mengubah suara menjadi teks (speech to text) dengan API Deepgram.
    • Tingkat 4 (paling menantang): pelanggan bisa menelepon agent. Kamu belajar WebSocket untuk mendengarkan secara langsung, menentukan giliran bicara, dan membuat agent menjawab dengan suara (text to speech).

    Kerjakan berurutan: selesaikan satu tingkat sampai aplikasinya berjalan, baru lanjut ke tingkat berikutnya. Aplikasi di bagian atas halaman ini sudah lengkap sampai Tingkat 4, jadi hasil akhirnya bisa kamu lihat kapan saja.

    Persiapan

    • Browser Chrome atau Edge versi terbaru.
    • Teks editor, misalnya VS Code. Ekstensi Live Server boleh dipakai, tapi tidak wajib.
    • Koneksi internet, karena Tailwind, API, dan pembaca PDF di Tingkat 2 dimuat dari internet.
    • API key Netra.
    • Untuk Tingkat 3 dan 4: mikrofon (bawaan laptop atau headset) dan API key Deepgram.

    Cara mendapatkan API key Netra

    1. Masuk ke dashboard Netra dan pilih organisasi yang benar.
    2. Isi saldo di menu Billing. Netra memakai saldo prabayar, jadi tanpa saldo permintaan akan ditolak.
    3. Buka menu API Keys, buat key baru, lalu langsung salin. Key lengkap hanya ditampilkan satu kali.

    Kalau sekolah sudah punya akun Netra, minta API key ke guru. Panduan resminya ada di dokumentasi Netra: Make your first request.

    Cara mendapatkan API key Deepgram

    1. Daftar atau masuk ke Deepgram Console.
    2. Pilih project di menu Projects kiri atas, buka Settings, lalu pilih API Keys.
    3. Pilih Create a New API Key, beri nama, lalu Create Key. Salin key-nya saat itu juga, karena Deepgram tidak akan menampilkannya lagi.

    Panduan resminya ada di dokumentasi Deepgram: Creating API Keys.

    Alur data di Tingkat 1

    1. Pemilik toko menulis informasi usaha di kolom Konteks teks.
    2. Script di index.html menyusun system prompt berisi aturan kerja dan konteks itu.
    3. Saat pelanggan bertanya, script mengirim system prompt beserta riwayat chat ke API Netra.
    4. Netra menjalankan model AI dan mengembalikan jawaban.
    5. Script menampilkan jawaban itu sebagai gelembung chat.

    Tingkat 2 menambah satu tahap sebelum tahap kedua: teks dari PDF dibaca, lalu digabung dengan konteks teks.

    Tingkat 3 menambah tahap sebelum tahap ketiga: suara pelanggan direkam, diubah menjadi teks oleh Deepgram, lalu dikirim sebagai pertanyaan biasa. Tingkat 4 menjalankan semuanya bergantian tanpa henti: Deepgram mendengarkan, Netra menjawab, Deepgram membacakan jawaban, lalu kembali mendengarkan.

    Tingkat 1: Dasar

    Customer service dengan konteks teks

    Di tingkat ini agent hanya membaca konteks dari kolom Konteks teks. Panel Pengaturan cukup berisi API key, model, dan konteks teks. Kolom PDF baru ditambahkan di Tingkat 2.

    Langkah 1

    Membuat tampilan di index.html

    Halaman dibagi menjadi dua panel: Pengaturan di kiri dan Chat di kanan. Di layar HP, kedua panel bertumpuk ke bawah. Untuk Tingkat 1, panel Pengaturan berisi kolom API key, Model, dan Konteks teks.

    Tailwind dipasang dengan satu tag script. Versi browser ini membaca class di HTML lalu membuat CSS-nya saat halaman dibuka, jadi kamu tidak perlu menjalankan npm.

    index.html
    <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4.1.11"></script>

    Setiap kolom isian punya label. Nilai atribut for pada label harus sama dengan id pada input. Dengan begitu label bisa diklik untuk fokus ke input, dan pembaca layar tahu nama kolomnya.

    index.html (disederhanakan)
    <label for="api-key" class="field-label">API key Netra</label>
<input id="api-key" type="password" autocomplete="off" spellcheck="false"
  placeholder="Tempel API key di sini" class="field">

    type="password" menyembunyikan isi key di layar.

    Gaya tampilan: token dan komponen

    Ciri tampilan aplikasi ini ada di garisnya: garis hitam tebal dengan sudut siku. Warnanya sengaja dibatasi, yaitu hitam, putih, warna kertas untuk latar, dan satu aksen kuning untuk hal yang paling penting: tombol Kirim, pesan pelanggan, dan peringatan.

    Warna ditulis sekali sebagai token di blok @theme, di dalam tag <style type="text/tailwindcss">. Dari token itu Tailwind membuat class seperti bg-accent dan bg-paper.

    index.html, bagian style
    @theme {
  --color-accent: #ffe14d;
  --color-paper: #f5f4ef;
}

    Deretan class yang dipakai berulang digabung menjadi satu class komponen dengan @apply. Contohnya class field yang dipakai semua kolom isian. Di dalamnya, min-h-11 membuat tinggi kolom 44 piksel, ukuran yang nyaman disentuh jari.

    index.html, bagian style
    .field { @apply min-h-11 w-full min-w-0 border-2 border-black bg-white px-3 text-sm placeholder:text-stone-600; }

    Pada elemen pembungkus kedua panel (id="app-main"), class lg:grid-cols-[22rem_minmax(0,1fr)] membuat dua kolom mulai layar lebar. Awalan lg: berarti aturan itu baru berlaku di layar 1024 piksel ke atas, sehingga di HP halaman tetap satu kolom.

    Semua kode JavaScript ditulis di dalam satu tag <script> di akhir <body>, masih di file index.html. Saat script berjalan, semua elemen HTML di atasnya sudah ada, jadi document.getElementById bisa menemukannya.

    Elemen HTML yang sering dipakai diambil sekali di awal, lalu disimpan di objek el. Potongan di bawah hanya sebagian, versi lengkapnya ada di bagian script index.html.

    Langkah 3

    Menyusun konteks dan system prompt

    Di Tingkat 1, konteks cukup diambil dari kolom Konteks teks. Teksnya diberi label [Catatan teks] supaya AI tahu dari mana informasi itu berasal.

    index.html, bagian script (versi Tingkat 1)
    function buildContext() {
  const text = el.contextText.value.trim();
  return text ? `[Catatan teks]\n${text}` : '';
}

    System prompt adalah pesan pertama dengan role system. Pelanggan tidak melihatnya, tetapi AI mengikutinya sebagai aturan kerja.

    index.html, bagian script
    function buildSystemPrompt() {
  const context = buildContext().slice(0, MAX_CONTEXT_CHARS);
  const rules = [
    'Kamu adalah customer service yang ramah, sopan, dan membantu.',
    'Jawab pertanyaan pelanggan hanya berdasarkan informasi di bagian KONTEKS.',
    'Jika informasinya tidak ada di KONTEKS, katakan terus terang bahwa kamu belum punya informasi itu, lalu sarankan pelanggan menghubungi admin.',
    'Jangan mengarang harga, stok, promo, atau kebijakan.',
    'Jawab singkat dan jelas, dengan bahasa yang dipakai pelanggan.',
    'Tulis jawaban sebagai teks biasa tanpa format Markdown.',
  ];
  return `${rules.join('\n')}\n\nKONTEKS:\n${context || '(kosong, belum ada informasi usaha)'}`;
}

    Aturan "jawab hanya berdasarkan KONTEKS" mencegah AI mengarang harga atau kebijakan toko. Coba hapus aturan itu, lalu tanyakan sesuatu yang tidak ada di konteks dan bandingkan jawabannya.

    Konteks dipotong di 60.000 karakter (MAX_CONTEXT_CHARS). Makin panjang konteks, makin banyak token yang dipakai, dan makin besar biayanya.

    Langkah 4

    Memanggil API Netra

    Contoh dari Netra memakai perintah curl di terminal:

    terminal
    curl -sS https://api.netra.sh/v1/chat/completions \
  -H "Authorization: Bearer $NETRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "model": "deepseek/deepseek-v4.1-flash",
  "messages": [{"role":"user","content":"Hello!"}],
  "max_tokens": 64,
  "reasoning": {"enabled":true}
}'

    Di browser, permintaan yang sama ditulis dengan fetch. Setiap -H menjadi isi headers, dan bagian -d menjadi body.

    index.html, bagian script
    async function askAgent(apiKey, model, messages) {
  let response;
  try {
    response = await fetch(API_URL, {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${apiKey}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model,
        messages,
        // Token penalaran ikut dihitung di max_tokens, jadi batasnya dibuat cukup longgar.
        max_tokens: 2048,
        reasoning: { enabled: true },
      }),
    });
  } catch {
    throw new Error('Tidak bisa terhubung ke server Netra. Periksa koneksi internet.');
  }

  const data = await response.json().catch(() => null);
  if (!response.ok) throw new Error(describeApiError(response.status, data));

  const reply = data?.choices?.[0]?.message?.content?.trim();
  if (!reply) throw new Error('Model tidak mengirim jawaban. Coba kirim ulang pertanyaannya.');
  return reply;
}

    Isi messages adalah daftar pesan, masing-masing dengan role: system untuk aturan, user untuk pertanyaan pelanggan, dan assistant untuk jawaban AI sebelumnya. API tidak mengingat percakapan, jadi seluruh riwayat dikirim ulang setiap kali pelanggan bertanya.

    index.html, bagian script
    const messages = [{ role: 'system', content: buildSystemPrompt() }, ...state.history];

    Jawaban AI ada di data.choices[0].message.content. Kalau status HTTP menandakan gagal (response.ok bernilai false), fungsi describeApiError mengubah kode status menjadi pesan yang mudah dipahami.

    Nilai max_tokens dibuat 2048, bukan 64 seperti contoh curl. Menurut dokumentasi chat request Netra, token yang dipakai model untuk berpikir (reasoning) termasuk token keluaran, sehingga batas 64 bisa membuat jawaban kosong atau terpotong. Sebaliknya, batas yang terlalu besar membuat Netra menahan saldo lebih banyak untuk setiap permintaan.

    Teks hasil berpikir model dikirim terpisah di choices[0].message.reasoning. Aplikasi ini hanya menampilkan content, yaitu jawaban untuk pelanggan.

    Langkah 5

    Menampilkan chat

    Setiap pesan dibuat dengan document.createElement, lalu teksnya dimasukkan lewat textContent.

    index.html, bagian script
    function createBubble(role, text) {
  const isUser = role === 'user';
  const wrapper = document.createElement('div');
  wrapper.className = `flex ${isUser ? 'justify-end' : 'justify-start'}`;

  const bubble = document.createElement('div');
  bubble.className = isUser ? 'bubble bubble-user' : 'bubble bubble-agent';

  const label = document.createElement('p');
  label.className = 'text-xs font-bold';
  label.textContent = isUser ? 'Pelanggan' : 'Agent';

  const body = document.createElement('p');
  body.className = 'mt-1 whitespace-pre-wrap break-words text-sm';
  body.textContent = text;

  bubble.append(label, body);
  wrapper.append(bubble);
  return wrapper;
}

    Kenapa textContent, bukan innerHTML?

    Jawaban AI bisa saja berisi teks seperti <img src=x onerror=alert(1)>. Kalau dimasukkan lewat innerHTML, browser menganggapnya HTML dan menjalankan kodenya. Lewat textContent, teks itu tampil apa adanya. Kebiasaan ini mencegah serangan yang disebut XSS (cross-site scripting). Di Tingkat 2, nama file PDF juga ditampilkan dengan cara yang sama.

    Tiga keadaan layar

    • Kosong: belum ada percakapan, jadi panel chat menampilkan petunjuk cara mulai.
    • Memuat: tombol berubah menjadi Mengirim... dan muncul tulisan Agent sedang menulis jawaban...
    • Error: kotak merah menjelaskan penyebabnya, dan pertanyaan dikembalikan ke kolom input supaya bisa dikirim ulang.

    Ketiganya diatur fungsi renderMessages yang membaca state.history, state.isSending, dan state.error.

    2. Salin contoh konteks di bawah ke kolom Konteks teks. Isinya data latihan, bukan toko sungguhan.
    3. Tanyakan "Hari Minggu buka tidak?". Agent seharusnya menjawab bahwa toko tutup.
    4. Tanyakan "Ada diskon untuk pelajar?". Info itu tidak ada di konteks, jadi agent seharusnya bilang belum punya informasinya dan menyarankan menghubungi admin.

    Menambahkan konteks dari dokumen PDF

    Langkah 7

    Membaca PDF dengan pdf.js

    JavaScript di browser tidak bisa langsung mengambil teks dari file PDF. Untuk itu kita memakai pdf.js, library pembaca PDF buatan Mozilla. Ukurannya cukup besar, jadi library ini baru diunduh saat pengguna memilih PDF untuk pertama kali.

    index.html, bagian script
    let pdfjsPromise = null;

// pdf.js baru diunduh saat pertama kali ada PDF, jadi halaman awal tetap ringan.
function loadPdfJs() {
  if (!pdfjsPromise) {
    pdfjsPromise = import(PDFJS_URL)
      .then((pdfjsLib) => {
        pdfjsLib.GlobalWorkerOptions.workerSrc = PDFJS_WORKER_URL;
        return pdfjsLib;
      })
      .catch((error) => {
        pdfjsPromise = null; // supaya bisa dicoba lagi setelah internet kembali
        throw error;
      });
  }
  return pdfjsPromise;
}

    Setelah library siap, teks dibaca halaman demi halaman:

    index.html, bagian script
    async function extractPdfText(file) {
  const pdfjsLib = await loadPdfJs();
  const data = new Uint8Array(await file.arrayBuffer());
  const pdf = await pdfjsLib.getDocument({ data }).promise;
  const pageCount = pdf.numPages;
  const pageTexts = [];

  for (let pageNumber = 1; pageNumber <= pageCount; pageNumber++) {
    const page = await pdf.getPage(pageNumber);
    const content = await page.getTextContent();
    // hasEOL menandai akhir baris di PDF, jadi baris asli tetap terjaga.
    const text = content.items.map((item) => item.str + (item.hasEOL ? '\n' : ' ')).join('');
    pageTexts.push(text.trim());
  }

  await pdf.destroy();
  const text = pageTexts.join('\n\n').replace(/[ \t]+/g, ' ').trim();
  return { pages: pageCount, text };
}

    Perhatikan kata await yang muncul berkali-kali. Membaca file, membuka PDF, dan mengambil teks tiap halaman butuh waktu, jadi setiap tahap ditunggu sampai selesai sebelum lanjut ke tahap berikutnya.

    Isi setiap halaman berupa potongan teks kecil (item.str) yang kita sambung satu per satu. Kalau item.hasEOL bernilai true, baris di PDF berakhir di situ, jadi kita tambahkan baris baru.

    Fungsi handlePdfFiles di script memanggil extractPdfText untuk setiap file yang dipilih, menyimpan hasilnya ke state.documents, lalu menulis statusnya. PDF hasil scan berisi gambar, bukan teks, sehingga hasilnya kosong. Aplikasi menolak file seperti itu dan menulis alasannya di bawah tombol pilih file.

    Langkah 8

    Menggabungkan teks PDF ke konteks

    Fungsi buildContext dari Langkah 3 diperluas. Setelah catatan teks, teks setiap PDF ditambahkan dengan label nama filenya.

    index.html, bagian script
    function buildContext() {
  const parts = [];
  const text = el.contextText.value.trim();
  if (text) parts.push(`[Catatan teks]\n${text}`);
  for (const doc of state.documents) {
    parts.push(`[Dokumen: ${doc.name}]\n${doc.text}`);
  }
  return parts.join('\n\n');
}

    buildSystemPrompt tidak perlu diubah sama sekali, karena fungsi itu hanya memanggil buildContext. Inilah untungnya memisahkan tugas ke fungsi-fungsi kecil.

    PDF bisa membuat konteks jauh lebih panjang. Kalau totalnya melebihi 60.000 karakter, kotak ukuran konteks di panel Pengaturan berubah kuning dan bagian akhir konteks akan dipotong.

    Mencoba Tingkat 2

    1. Di aplikasi di bagian atas, unggah PDF yang berisi teks, misalnya daftar harga.
    2. Periksa daftar PDF dan jumlah karakter konteks di panel Pengaturan.
    3. Tanyakan sesuatu yang hanya ada di PDF itu. Agent seharusnya menjawab dari isi PDF.
    4. Unggah PDF hasil scan. Aplikasi seharusnya menolaknya dengan alasan tidak ada teks.

    Tingkat 3: Input suara

    Bertanya lewat rekaman suara

    Di tingkat ini pelanggan menekan tombol Rekam, bicara, lalu menekan Selesai. Rekaman dikirim ke Deepgram, layanan speech to text yang mengubah suara menjadi teks. Teks itu lalu dikirim ke agent persis seperti pertanyaan yang diketik.

    Langkah 10

    Merekam suara dengan MediaRecorder

    Browser punya dua alat bawaan untuk merekam. navigator.mediaDevices.getUserMedia meminta izin lalu membuka mikrofon, dan MediaRecorder merekam suaranya. Fungsi getMicrophone di script membungkus langkah pertama dan mengubah error izin menjadi pesan yang mudah dipahami.

    index.html, bagian script
    async function startRecording() {
  const stream = await getMicrophone();
  const chunks = [];
  recorder = new MediaRecorder(stream);
  recorder.addEventListener('dataavailable', (event) => {
    if (event.data.size > 0) chunks.push(event.data);
  });
  recorder.addEventListener('stop', () => {
    stream.getTracks().forEach((track) => track.stop()); // mematikan mikrofon
    const audio = new Blob(chunks, { type: chunks[0]?.type || 'audio/webm' });
    recorder = null;
    handleRecording(audio);
  });
  recorder.start();
  // Rekaman berhenti sendiri setelah batas waktu, supaya mikrofon tidak lupa dimatikan.
  recordingTimer = setTimeout(stopRecording, MAX_RECORDING_SECONDS * 1000);
}

function stopRecording() {
  clearTimeout(recordingTimer);
  if (recorder?.state === 'recording') recorder.stop();
}

    Selama merekam, MediaRecorder mengirim potongan audio lewat event dataavailable, dan potongan itu dikumpulkan di chunks. Saat rekaman dihentikan, event stop menggabungkan semua potongan menjadi satu Blob, yaitu file audio di memori browser. Di Chrome dan Edge formatnya WebM.

    Jangan lupa track.stop(). Tanpa baris itu mikrofon tetap menyala dan tanda merekam di tab browser tidak hilang.

    Browser hanya mengizinkan mikrofon di halaman yang aman: alamat https://, localhost, atau file yang dibuka langsung dari komputer. Halaman http:// biasa tidak bisa merekam.

    Langkah 11

    Mengubah suara menjadi teks dengan Deepgram

    Contoh dari dokumentasi Deepgram memakai curl. Ada dua perbedaan dengan Netra: header-nya ditulis Token, bukan Bearer, dan isi permintaannya adalah file audio itu sendiri, bukan JSON.

    terminal
    curl -sS "https://api.deepgram.com/v1/listen?model=nova-3&language=id&smart_format=true" \
  -H "Authorization: Token $DEEPGRAM_API_KEY" \
  -H "Content-Type: audio/webm" \
  --data-binary @rekaman.webm

    Pengaturannya ditulis di alamat URL, setelah tanda tanya:

    • model=nova-3: model speech to text Deepgram yang paling akurat untuk pemakaian umum.
    • language=id: Bahasa Indonesia. Tanpa ini, Deepgram menganggap suaranya berbahasa Inggris.
    • smart_format=true: menambah tanda baca, dan menulis angka, tanggal, serta jam dengan format yang mudah dibaca.
    index.html, bagian script
    // nova-3 adalah model speech to text Deepgram yang paling akurat untuk pemakaian umum. language=id: Bahasa Indonesia.
const DEEPGRAM_LISTEN_URL = 'https://api.deepgram.com/v1/listen?model=nova-3&language=id&smart_format=true';

    Di browser, perintah curl itu ditulis dengan fetch. File rekaman (Blob) langsung menjadi body, dan jenis filenya dikirim di header Content-Type.

    index.html, bagian script
    async function transcribeAudio(apiKey, audio) {
  let response;
  try {
    response = await fetch(DEEPGRAM_LISTEN_URL, {
      method: 'POST',
      headers: {
        Authorization: `Token ${apiKey}`,
        'Content-Type': audio.type,
      },
      body: audio, // file rekaman dikirim apa adanya, bukan JSON
    });
  } catch {
    throw new Error('Tidak bisa terhubung ke server Deepgram. Periksa koneksi internet.');
  }

  const data = await response.json().catch(() => null);
  if (!response.ok) throw new Error(describeDeepgramError(response.status, data));

  const text = data?.results?.channels?.[0]?.alternatives?.[0]?.transcript?.trim();
  if (!text) throw new Error('Suara tidak terdengar jelas. Dekatkan mikrofon, lalu rekam ulang.');
  return text;
}

    Teks hasilnya ada di results.channels[0].alternatives[0].transcript. Kalau teksnya kosong, Deepgram tidak menemukan satu kata pun, misalnya karena suaranya terlalu pelan.

    Terakhir, teks itu dimasukkan ke kolom pertanyaan, lalu form dikirim dengan requestSubmit(). Dengan cara ini pertanyaan dari suara melewati jalur yang sama dengan pertanyaan yang diketik, termasuk pengecekan API key Netra dan tampilan error.

    index.html, bagian script

    Tingkat 4: Panggilan suara

    Menelepon customer service

    Di tingkat ini pelanggan menekan Telepon, lalu mengobrol tanpa menekan tombol lagi, seperti menelepon. Agent menyapa, mendengarkan, lalu menjawab dengan suara. Tiga proses bekerja bergantian:

    Langkah 13

    Mendengarkan langsung lewat WebSocket

    Di Tingkat 3, suara baru dikirim setelah rekaman selesai. Untuk telepon, suara harus dikirim terus selagi pelanggan bicara. fetch tidak cocok untuk itu, jadi dipakai WebSocket: sambungan dua arah yang tetap terbuka. Aplikasi mengirim potongan audio, dan Deepgram membalas dengan teks.

    index.html, bagian script
    // Versi streaming untuk panggilan. endpointing=500: potongan kalimat baru ditutup setelah diam 0,5 detik.
// Deepgram mengirim UtteranceEnd setelah pelanggan diam 1 detik.
const DEEPGRAM_LIVE_URL = 'wss://api.deepgram.com/v1/listen?model=nova-3&language=id&smart_format=true&interim_results=true&endpointing=500&utterance_end_ms=1000';

    Ada tiga pengaturan baru:

    • interim_results=true: Deepgram mengirim teks sementara selagi pelanggan masih bicara.
    • endpointing=500: Deepgram baru menutup satu potongan kalimat setelah pelanggan diam 0,5 detik. Nilai bawaannya hanya 10 milidetik. Saat aplikasi ini diuji dengan nilai bawaan, kalimat terpotong di jeda kecil dan beberapa kata di tengahnya hilang. Dokumentasi Deepgram menyarankan 300 sampai 500 milidetik untuk percakapan.
    • utterance_end_ms=1000: Deepgram mengirim pesan UtteranceEnd setelah pelanggan diam 1 detik. Pesan inilah tanda giliran agent menjawab.

    Browser tidak bisa menambah header Authorization ke WebSocket. Sebagai gantinya, Deepgram menerima API key lewat subprotocol, yaitu daftar ['token', apiKey] di argumen kedua.

    index.html, bagian script
    function openDeepgramSocket(apiKey) {
  return new Promise((resolve, reject) => {
    // Browser tidak bisa menambah header Authorization ke WebSocket, jadi API key dikirim lewat subprotocol.
    const socket = new WebSocket(DEEPGRAM_LIVE_URL, ['token', apiKey]);
    socket.addEventListener('open', () => resolve(socket));
    socket.addEventListener('error', () => {
      reject(new Error('Panggilan gagal tersambung ke Deepgram. Periksa API key Deepgram dan koneksi internet.'));
    });
  });
}

    Setelah tersambung, perekam dijalankan dengan start(250): potongan audio dikirim setiap 250 milidetik, tanpa menunggu rekaman selesai. Deepgram juga menutup koneksi yang 10 detik tidak menerima apa pun. Saat agent bicara, rekaman dijeda, jadi aplikasi mengirim pesan KeepAlive setiap 5 detik.

    index.html, bagian script (potongan startCall)

    Menentukan giliran agent

    Setiap pesan dari Deepgram diolah oleh handleCallMessage. Pesan Results berisi teks. Kalau is_final bernilai false, teksnya masih sementara dan bisa berubah, jadi hanya ditampilkan di bar panggilan. Kalau true, teksnya disimpan.

    index.html, bagian script
    function handleCallMessage(event) {
  // Selama agent berpikir atau bicara, hasil dari Deepgram diabaikan.
  if (state.callStatus !== 'listening') return;
  const data = JSON.parse(event.data);

  if (data.type === 'Results') {
    const text = data.channel.alternatives[0].transcript;
    // Hasil sementara (is_final false) masih bisa berubah, jadi hanya hasil final yang disimpan.
    if (data.is_final) {
      if (text) call.heardText = `${call.heardText} ${text}`.trim();
      call.interimText = '';
    } else {
      call.interimText = text;
    }
    el.callTranscript.textContent = `${call.heardText} ${call.interimText}`.trim();
  }

  // UtteranceEnd: pelanggan sudah diam 1 detik setelah kata terakhir.
  if (data.type === 'UtteranceEnd' && (call.heardText || call.interimText)) call.turnEnded = true;

  // UtteranceEnd kadang datang sebelum hasil final kalimat terakhir, jadi tunggu sampai tidak ada teks sementara.
  if (call.turnEnded && !call.interimText && call.heardText) answerCustomer(call.heardText);
}

    Kenapa tidak langsung menjawab begitu UtteranceEnd datang? Saat aplikasi ini diuji, UtteranceEnd pernah tiba sedikit lebih dulu daripada hasil final kalimat terakhir, sehingga agent menjawab kalimat yang terpotong. Karena itu aplikasi menunggu sampai tidak ada lagi teks sementara.

    Memutar suara sebelum selesai diunduh

    Deepgram mulai mengirim suara kurang dari satu detik setelah diminta, tetapi file lengkapnya baru selesai beberapa detik kemudian. Kalau aplikasi menunggu file lengkap, pelanggan menunggu dalam diam. Fungsi streamAudio memakai MediaSource untuk memutar setiap potongan suara begitu tiba.

    index.html, bagian script
    // Suara diputar sambil potongan berikutnya masih diunduh, jadi agent mulai bicara lebih cepat.
function streamAudio(response) {
  const mediaSource = new MediaSource();
  const audio = new Audio(URL.createObjectURL(mediaSource));
  mediaSource.addEventListener('sourceopen', async () => {
    const buffer = mediaSource.addSourceBuffer('audio/mpeg');
    const reader = response.body.getReader();
    try {
      for (;;) {
        const { done, value } = await reader.read();
        if (done) break;
        buffer.appendBuffer(value);
        await new Promise((resolve) => buffer.addEventListener('updateend', resolve, { once: true }));
      }
      mediaSource.endOfStream();
    } catch {
      if (mediaSource.readyState === 'open') mediaSource.endOfStream('network');
    }
  }, { once: true });
  return audio;
}

    Browser yang belum mendukung cara ini memakai jalur cadangan di createAgentAudio: menunggu file lengkap, baru memutarnya.

    Catatan keamanan

    Di aplikasi ini API key Netra dan Deepgram dipakai langsung dari browser. Siapa pun yang membuka DevTools di komputer itu bisa melihat key-nya. Dokumentasi Netra sendiri meminta key disimpan di server, bukan di kode yang berjalan di browser.

    • Pakai pola ini hanya untuk belajar di komputer sendiri.
    • Jangan unggah API key ke GitHub, dan jangan mengirimnya lewat chat.
    • Kalau key tersebar, cabut (revoke) key itu di dashboard Netra atau Deepgram Console, lalu buat yang baru.
    • Untuk website sungguhan, buat server kecil yang menyimpan key dan meneruskan permintaan ke Netra dan Deepgram. Deepgram juga menyediakan token sementara yang dibuat server dan hanya berlaku sebentar, sehingga API key asli tidak pernah sampai ke browser.
    • Rekaman suara pelanggan dikirim ke server Deepgram untuk diubah menjadi teks. Beri tahu pengguna sebelum mereka merekam, dan jangan minta mereka menyebut data rahasia seperti PIN atau nomor kartu.

    2. Tambahkan tombol Salin di setiap gelembung jawaban agent. Petunjuk: navigator.clipboard.writeText().
    3. Kirim hanya 10 pesan terakhir ke API supaya token lebih hemat. Petunjuk: state.history.slice(-10).
    4. Ganti reasoning: { enabled: true } menjadi { enabled: false }, lalu bandingkan kecepatan dan isi jawabannya. Menurut dokumentasi Netra, enabled: true memakai tingkat berpikir high.

    Tingkat 2

    1. Tampilkan 100 karakter pertama teks setiap PDF di bawah nama filenya, supaya pemilik toko bisa memastikan teksnya terbaca benar. Petunjuk: doc.text.slice(0, 100).
    2. Tantangan: tampilkan jawaban sedikit demi sedikit dengan streaming. Baca panduan streaming Netra.

    Tingkat 3

    1. Jangan langsung kirim hasil rekaman. Masukkan teksnya ke kolom pertanyaan saja, supaya pelanggan bisa memperbaikinya sebelum menekan Kirim. Petunjuk: hapus baris el.chatForm.requestSubmit() di handleRecording.
    2. Tampilkan lama rekaman dalam detik selagi merekam. Petunjuk: setInterval, seperti jam di bar panggilan Tingkat 4.

    Tingkat 4

    1. Ganti suara agent, misalnya ke aura-2-thalia-en atau aura-2-nestor-es, lalu bandingkan mana yang paling jelas membaca bahasa Indonesia. Daftar suaranya ada di dokumentasi suara Deepgram.
    2. Buat agent menjawab lebih cepat saat telepon dengan mematikan reasoning khusus untuk panggilan. Petunjuk: tambahkan parameter baru di askAgent.
    3. Tantangan: biarkan pelanggan memotong agent yang sedang bicara. Petunjuk: jangan jeda perekam, tambahkan vad_events=true di URL WebSocket, lalu hentikan suara agent saat Deepgram mengirim pesan SpeechStarted. Pakai headset, supaya suara agent tidak tertangkap mikrofon.

    Contoh project belajar: HTML, Tailwind, dan JavaScript tanpa server. API key tersimpan di browser, jadi jangan pakai pola ini untuk website publik.

    Referensi: dokumentasi Netra, pdf.js, dokumentasi Deepgram, dan dokumentasi Tailwind CSS.
